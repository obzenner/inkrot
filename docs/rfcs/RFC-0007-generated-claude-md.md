# RFC-0007: Generated CLAUDE.md with README Symlink

## Problem

The repo has no CLAUDE.md. Without one, agents working on this project have no top-level orientation. A hand-written CLAUDE.md would drift from schemas the same way hand-written skills did.

Additionally, README.md is expected by GitHub. Maintaining both is a SSOT violation.

## Proposal

`CLAUDE.md` is generated by a **repo-level** script (`scripts/gen_claude_md.py`) from `CLAUDE.md.tmpl` at the repo root. `README.md` is a symlink to `CLAUDE.md`. Both are write-protected by repo-level hooks in `.claude/settings.json`.

This is explicitly **not** part of the plugin. The plugin ships to consumers and knows nothing about the project's CLAUDE.md. Generation of CLAUDE.md is project-level tooling — it reads the plugin's schemas and templates to derive content, but it lives outside the plugin directory.

### Boundary

| Concern | Location | Purpose |
|---------|----------|---------|
| SKILL.md generation | `plugins/docs-toolkit/scripts/gen_skills.py` | Plugin-internal: generates skill files + asset templates from schemas |
| CLAUDE.md generation | `scripts/gen_claude_md.py` | Repo-level: generates project docs from schemas + skill templates |
| Freshness enforcement | `scripts/check_freshness.py` | Repo-level: SessionStart/Stop hook for this repo only |
| Write protection (plugin) | `plugins/docs-toolkit/scripts/protect_generated.py` | Plugin hook: blocks edits to generated SKILL.md in consumer repos |
| Write protection (repo) | `.claude/settings.json` PreToolUse hook | Repo-level: blocks edits to CLAUDE.md in this repo |

### What CLAUDE.md contains (schema-derived)

| Section | Source |
|---------|--------|
| Available document types | All non-skill schemas: type, naming, statuses |
| Default discovery paths | `discovery.defaults` from each schema |
| Available skills | Glob `plugins/docs-toolkit/skills/*/SKILL.md.tmpl` — name + description from frontmatter |

### What CLAUDE.md contains (static in template)

| Section | Content |
|---------|---------|
| Plugin identity | Name, purpose, one-line description |
| Installation | Exact marketplace commands |
| Architecture | schemas → gen_skills → SKILL.md → hooks |

### Template design

`CLAUDE.md.tmpl` lives at repo root. Placeholders:

- `{{DOC_TYPES_TABLE}}` — types, naming, sections, statuses from schemas
- `{{DEFAULT_PATHS}}` — discovery defaults from schemas
- `{{SKILLS_TABLE}}` — skill name + description from each .tmpl frontmatter
- `{{SCHEMA_COUNT}}` — count of doc type schemas

### gen_claude_md.py

Repo-level script at `scripts/gen_claude_md.py`:
1. Reads schemas from `plugins/docs-toolkit/schemas/`
2. Reads skill templates from `plugins/docs-toolkit/skills/*/SKILL.md.tmpl`
3. Renders `CLAUDE.md.tmpl` → `CLAUDE.md`
4. Supports `--dry-run` (exit 1 if stale)

### README.md

```bash
ln -sf CLAUDE.md README.md
```

Git tracks the symlink. No generation needed.

### Write protection

In `.claude/settings.json` (repo-level, not plugin hooks):

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "uv run scripts/protect_claude_md.py"
          }
        ]
      }
    ]
  }
}
```

This blocks writes to `CLAUDE.md` at the repo root. Separate from the plugin's `protect_generated.py` which ships to consumers.

## Alternatives

- **Generate CLAUDE.md inside the plugin's gen_skills.py:** Rejected — conflates plugin-internal generation with repo-level concerns. The plugin shouldn't know about the project's CLAUDE.md.
- **Hand-written CLAUDE.md with lint check:** Rejected — same drift problem RFC-0006 addressed.
- **README.md as source, CLAUDE.md as symlink:** Rejected — CLAUDE.md is the canonical name for agent consumption.
- **No README, just CLAUDE.md:** Viable but GitHub renders README.md by default. Symlink costs nothing.

## Resolution

Draft. Pending implementation.
