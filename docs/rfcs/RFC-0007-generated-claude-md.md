# RFC-0007: Generated CLAUDE.md with README Symlink

## Problem

The plugin has no CLAUDE.md. Without one, agents consuming this plugin have no top-level orientation — they must discover capabilities by reading individual SKILL.md files, schemas, and hooks. A hand-written CLAUDE.md would drift from schemas the same way hand-written skills did (the problem RFC-0006 solved).

Additionally, a README.md is expected by GitHub for repo presentation. Maintaining both files is a SSOT violation — the content is identical.

## Proposal

`CLAUDE.md` is generated by `gen_skills.py` from a `CLAUDE.md.tmpl` template at the plugin root. `README.md` is a symlink to `CLAUDE.md`. Both are write-protected by the hook.

### What CLAUDE.md contains (schema-derived)

| Section | Source |
|---------|--------|
| Available document types | All non-skill schemas: type, naming, statuses |
| Default discovery paths | `discovery.defaults` from each schema |
| Available skills | Glob `skills/*/SKILL.md.tmpl` — name + description from frontmatter |
| Validation rules summary | Compact summary of what `validate.py` enforces |

### What CLAUDE.md contains (static in template)

| Section | Content |
|---------|---------|
| Plugin identity | Name, purpose, one-line description |
| Quick start | How to use in a project |
| Architecture overview | schemas → gen_skills → SKILL.md → hooks |
| Contributing | How to add a new doc type or skill |

### Template design

`CLAUDE.md.tmpl` lives at plugin root. New placeholders:

- `{{DOC_TYPES_TABLE}}` — reuse existing renderer
- `{{DEFAULT_PATHS}}` — reuse existing renderer
- `{{SKILLS_TABLE}}` — new: lists each skill's name + description from its .tmpl frontmatter
- `{{SCHEMA_COUNT}}` — number of doc type schemas

### gen_skills.py changes

1. Discover `CLAUDE.md.tmpl` at plugin root (not inside `skills/`)
2. Render it with the same placeholder registry + new `{{SKILLS_TABLE}}` and `{{SCHEMA_COUNT}}`
3. Write to `CLAUDE.md` at plugin root

### README.md

```bash
ln -sf CLAUDE.md README.md
```

Created once (manually or by script). Git tracks the symlink. No generation needed.

### protect_generated.py changes

Add `CLAUDE.md` to the protected set:

```python
GENERATED_PATTERNS = [
    re.compile(r"^skills/[^/]+/SKILL\.md$"),
    re.compile(r"^skills/create-document/assets/[a-z]+-template\.md$"),
    re.compile(r"^CLAUDE\.md$"),
]
```

`README.md` is a symlink — writes to it resolve to `CLAUDE.md` which is already blocked.

## Alternatives

- **Hand-written CLAUDE.md with lint check:** Rejected — same drift problem RFC-0006 addressed for skills.
- **README.md as the source, CLAUDE.md as symlink:** Rejected — CLAUDE.md is the canonical name for agent consumption. README is the GitHub presentation layer, not the SSOT.
- **Generate both files independently:** Rejected — SSOT violation. One file, one symlink.
- **No README, just CLAUDE.md:** Viable but GitHub renders README.md by default. Symlink costs nothing.

## Resolution

Draft. Pending implementation.
